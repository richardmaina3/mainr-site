# Architecture

Full design source of truth: `planning/engineering_design.md`. This file tracks what is **actually built**, and is updated as components land.

## Overview

A static, single-page Astro site with two phases. In the **authoring/build phase**, JSON content files (validated by Zod schemas) and photos filtered by a sharp-based script (warm tint, film grain, EXIF stripped) feed an `astro build` that renders the sections to static HTML and generates responsive AVIF/WebP images. In the **runtime phase**, the resulting `dist/` folder is served as static files from Netlify's CDN, with fonts loaded from Google Fonts. There is no backend, database or client-side framework.

Page order: Header, Hero, Work, Cooking, Culture, Footer.

## Components

Build phases 1 (scaffold), 2 (content layer) and 3 (photo pipeline) are done. Phase 4 (components) is done: UI primitives, Header, Hero, Work, Cooking, Culture and Footer are all built. Phase 5 (responsive pass) is done: the page was audited at 17 sizes with no overflow, clipping or layout shift, and tap targets were enlarged (44px minimum on phones). The page is 27 KB of HTML, 18 KB of CSS, 213 KB of images and a single 235-byte inline script (the mobile menu). One entry is added per component as it lands.

| Content layer (`src/content/*.json`, `content.config.ts`) | Built (phase 2), placeholder content | Six collections via `file()` plus a custom parser that wraps each plain JSON file as one entry. Zod enforces required `alt`, valid image paths (relative to the JSON file), tiers 1 to 6. Verified: build passes on starter content and fails on an empty `alt` and on a wrong image path. | Placeholder images (`src/assets/photos/*`) | All real | 14 processed JPEG masters (hero portrait, 5 dishes, 4 albums, 2 museum, 2 sports) in one flat folder. No placeholder images remain. |
| Photo pipeline (`scripts/process-photos.mjs`, `scripts/photo-filter.config.json`, `npm run photos`) | Built (phase 3), all 14 photos processed | Flat in (`media-originals/`) and flat out (`src/assets/photos/`). Per image: EXIF orientation, optional per-photo corrections, 1600px cap, contrast and saturation, warm tint, light film grain (strength 0.1), JPEG q90 with all metadata stripped. Output names are lowercased and hyphenated; duplicate names stop the run; unsupported files (e.g. HEIC) are skipped with a warning; skips images newer than both the original and the config. Tested on a synthetic image with EXIF and GPS, then run on every photo (all outputs verified metadata-free). `sharp` is a direct dependency (0.35.5). EXIF orientation via `autoOrient()`. An optional per-photo `adjustments` map in the config holds `rotate`, `crop`, `whiteBalance` and `tameBlues` (validated; unknown keys stop the run): used for the sideways OKC-PHX photo and the hero portrait (crop, warmer white balance, calmer blue backdrop). |
| Design tokens and global styles | Built (phase 1) | `src/styles/tokens.css` (colours, shadows, fonts, fluid `clamp()` type and spacing) and `global.css` (16px hairline grid, `.page` column, focus, skip link, reduced motion). Verified at 320 to 1920px: no horizontal scroll. |
| Base layout (`BaseLayout.astro`) | Built (phase 1) | Head, meta and og tags, canonical from `SITE_URL`, favicon, self-hosted fonts (4 families, `src/styles/fonts.css`, headline and body fonts preloaded), share image meta (`og:image` with size and alt). Props are `title`, `description`, `ogImage?`; `index.astro` feeds them from `site.json`. |
| Page (`index.astro`) | Built (phase 4) | Header, Hero, Work, Cooking, Culture and Footer. Still loads every content collection, so bad content fails the build even for sections not built yet. Calls `warnOnContent()`. Work, Cooking, Culture and Footer are added step by step. |
| UI components: PillButton, PixelIcon, Sticker, Tape, Polaroid, StickyNote | Built (phase 4 step 1) | `src/components/ui/`. Decorative pieces (`Tape`, `Sticker`, icons) are `aria-hidden`. |

Matches the mockup's window and column measurements at 1280px. No horizontal scroll from 320px to 1920px. |
| Cooking grid (intro cell, 5 DishCells) | Built (phase 4 step 3) | `Cooking.astro` (grid, intro cell, filler cells) and `DishCell.astro`. Corner-anchored in a max-400px centred stage so it holds at the 341px cells of the 1100px breakpoint. Phones: annotation as a caption, no arrow. Filler cells pad the last row, so adding a dish needs no code. Matches the mockup at 1280px. "More plates" not built (out of v1). |

Matches the mockup at 1280px; no overlaps or overflow from 320px to 1920px. |
